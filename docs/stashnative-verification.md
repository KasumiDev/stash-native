# Verification and manual TV checklist

The simulator and host checks exercise Stash data, UI, software media, and pure activity accounting. They cannot establish LG hardware playback, video-plane composition, TV decoder performance, or long-running memory stability.

The implementation includes synthetic route fixtures (`STASH_FIXTURES=1`, host only), a synthetic animated WebP generated by tests, and a short synthetic MP4 for the native software preview decoder. No private library media is included. GraphQL selections and ordering were checked read-only against Stash v0.31.1. The startup playback fix was installed on the target TV and the owner confirmed playback works; scene 19 was authorized for playback history. O-count testing remains a separate explicit action.

Run the final host gates on the committed tree with `make check` and the nightly `--no-default-features` command in the setup guide. The ARM64 GitHub Actions job builds ARM32 ELF, checks package assertions, and grades firmware linkage against its compatibility inventory. Artifact and check status belong to the exact commit shown in that run.

Firmware source review confirmed the preview wrapper uses matching bundled FFmpeg headers and absolute suffixed library paths, rather than firmware FFmpeg. The inventory's lowest graded image is webOS 4.4.2; the target TV reports 4.4.0, so a passing inventory grade does not prove that exact firmware.

## Tests you perform after installing

1. Open every section and detail route. Check arrows, focus, Back, search, sort, loading/error/retry, and automatic pagination in pages of 50. Check Home favorites appear before nonfavorites. The shared top menu should retain the original profile-chip and centered-tab layout. Scene collections use a four-column landscape grid with full portrait thumbnails fitted inside cells; Tags use square cards. Shelves use the shared card-row carousel renderer. After loading several pages, return from details and confirm the focused item and scroll position survive refresh.
2. Leave a scene focused for at least 700 ms. Confirm one muted preview loops and stops immediately on focus loss, navigation, and full playback. A missing or failed preview should retain the still.
3. View a shelf of animated performer portraits. Confirm visible portraits animate and off-screen work stops. Assets exceeding the shared decoded-media budget retain stills.
4. Open a gallery, navigate previous/next, and run slideshows at three, five, and ten seconds.
5. Play the dedicated test scene. Exercise timeline Enter/OK, physical remote pause/resume, and seeking. The overlay omits audio/subtitle settings buttons. Check position and watched duration after at least 30 seconds, then stop and resume. At natural completion, resume position should clear and the end screen should offer Replay and an explicit O +1 action. Episode and intro controls are absent.
6. Press O +1 once and hold the key. Confirm one intentional activation yields one increment and displayed counts refresh. Further activations within two seconds or while the request is pending must be rejected, including on the completion screen.
7. Repeat at least 100 preview focus changes and observe resource usage. This has not been performed on the TV by the assistant.
8. With the Magic Remote cursor still visible, click a scene and each player control. A release over the selected card must activate once; pressing and moving away before release must cancel. The wheel must activate the cursor and hover focus immediately, including after D-pad navigation. A fresh D-pad press must hide the cursor and take over focus. Check partially visible cards at shelf edges reveal as focus moves. The Stash SDL adapter uses the shared pointer, drag, release, key, and wheel bridge.
9. On Home, use Left/Right at the Play/Info action edges to change scenes. There are no separate previous/next buttons. Check directional slide motion, muted incoming hero previews, eight-second rotation, and outgoing still fallback. Scene Details also previews its backdrop. Enter Performer Details: its portrait, dimmed still backdrop, biography, available facts, model tags, and five popular scene tags should appear before favorite-tag shelves and the scene grid. Scroll down until the entire hero leaves view: a separate pinned name should fade in below navigation, then fade out when scrolling back. Check the compact shelf spacing with expanded card captions.
10. Open Search. The scene-search field should immediately own focus and open the TV keyboard. Type quickly and confirm only the latest results land. Empty input should not fetch the whole library.
11. During playback, check long titles remain clear of the icons. Up from the timeline or marker row reaches O +1; Up again hides the overlay. Down from O +1 returns to the timeline; Down again expands the marker row. Selecting a marker seeks without changing paused/playing state, including server-transcoded streams. Up from a marker collapses the row and focuses O +1. Marker screenshots use the still cache; after 700 ms of stable focus, one muted software preview may play while the hardware video continues. Verify simultaneous composition and performance on the TV; failed previews retain the screenshot. Scenes without markers omit the row.
12. Browse still thumbnails, close the app, and reopen it. Still artwork should reload from the bounded disk cache; animated portraits may show their cached still while fetching animation. Video previews and animated frames are not persisted. Confirm animation and memory behavior on the actual TV; host results cannot establish those properties.

Use dedicated test content for history and counter writes. Do not automatically retry a timed-out additive mutation: the server may already have applied it.

See [setup and installation](stashnative-setup.md). Stable release publication is not part of this debug handover.
